# Stage 11 Architecture Decision Records

## ADR-149 — Treat the capstone as a non-authorizing evidence package
**Status:** Accepted.  
**Context:** NorthStar needs a final consolidated package, but production activation remains outside the current architecture.  
**Decision:** Introduce `CAPSTONE-001/1.0.0` as a governed collection of reconciled architecture, traceability, threat, evaluation, RACI, runbook, cost, capacity and readiness evidence. Every output has `authority_effect: none`.  
**Alternatives:** Let the readiness evaluator activate a route; use a manual checklist without machine-readable evidence.  
**Rationale:** Evidence and deployment authority must remain separate.  
**Consequences:** The package can support accountable review but cannot approve, deploy or finalize.  
**Risks:** Stakeholders may mistake completeness of documentation for production readiness.  
**Mitigation:** The final assessment explicitly reports `denied` and `production_route_enabled=false`.  
**Review trigger:** A separately authorized deployment control plane is implemented.

## ADR-150 — Retain one active agent with specialized graph work units
**Status:** Accepted.  
**Context:** The final comparison must decide whether the inactive multi-agent alternative is justified.  
**Decision:** Retain exactly one active `AGT-001/1.1.0`, specialized `GRAPH-001/1.12.0` work units and formal task profiles. Keep `WP-008`, MCP/A2A peers and additional agents `inactive_future`.  
**Alternatives:** Supervisor-specialist agents; peer handoffs; distributed autonomous agents.  
**Rationale:** Current tasks share state, authority, lifecycle, tools, memory scope, termination and human approval. Representative evidence has not shown a material quality or latency advantage that exceeds coordination cost and security surface.  
**Consequences:** Lower operational and authorization complexity; future independent boundaries require a new ADR and evidence.  
**Review trigger:** A hard independent boundary or representative repeated-trial benefit is demonstrated.

## ADR-151 — Reconcile through an explicit compatible overlay
**Status:** Accepted with exception.  
**Decision:** Advance to `1.18.0` using merge-compatible overlays and record the absence of a byte-exact cumulative Git tree as an unresolved production blocker. Do not invent missing historical register detail.  
**Rationale:** The supplied Stage 10C handoff is authoritative for the current baseline, but the full historical repository is not mounted.  
**Review trigger:** A signed, byte-exact repository and artefact history is available.

## ADR-152 — Use conjunctive hard blockers, not a weighted readiness score
**Status:** Accepted.  
**Decision:** Production is denied when any hard blocker remains. No aggregate score, error budget, cost benefit or majority vote can compensate for missing authorization, audit, security, integrity, approved SLO/DR, Stage 8D/9D or provenance evidence.  
**Rationale:** A weighted score can hide catastrophic gaps.  
**Review trigger:** None; only blocker definitions and evidence may change through governance.

## ADR-153 — Keep the certification assignment educational
**Status:** Accepted.  
**Decision:** The final assignment and rubric assess architectural skill only. They do not certify NorthStar, the reader, a product or legal compliance.  
**Review trigger:** An accredited certification body defines a separate scheme.

## ADR-154 — Prefer current primary sources and mark evolving guidance
**Status:** Accepted.  
**Decision:** The annotated bibliography prioritizes official standards, standards bodies, primary project documentation and original guidance. Rapidly changing material is stamped `verified 2026-08-01`; preview or evolving status is identified.  
**Review trigger:** Publication changes or later playbook edition.

## ADR-155 — Bind the final release manifest locally without claiming enterprise provenance
**Status:** Accepted.  
**Decision:** The Stage 11 package includes SHA-256 hashes and a final release manifest. These detect accidental drift in the delivered package but are not signatures, trusted timestamps, WORM evidence or an enterprise software-supply-chain attestation.  
**Review trigger:** Enterprise signing, KMS/HSM and admission infrastructure exists.

## ADR-156 — Close the tutorial while carrying an implementation backlog
**Status:** Accepted.  
**Decision:** Stage 11 is the final tutorial stage. Unresolved blockers become an accountable implementation backlog; they do not create a Stage 12 or become silently accepted.  
**Review trigger:** A new edition or separately chartered implementation programme.
