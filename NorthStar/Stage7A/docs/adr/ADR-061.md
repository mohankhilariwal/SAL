# ADR-061 — Cooperative cancellation, deadlines and checkpoint resumption

- **Status:** Accepted
- **Stage:** S07A
- **Architecture version:** 1.6.0

## Context

The S06C architecture could carry canonical handoff semantics across one serialized boundary but could not execute independent regulatory-analysis work concurrently or asynchronously. Any change must preserve exactly one active `AGT-001`, application-owned state and routes, external human authority, gateway-only tools and canonical handoff semantics.

## Decision

Use cooperative cancellation events, propagated deadlines and atomic local checkpoints. Resume only incomplete branches and preserve completed results. Cancellation never approves, finalizes or changes the CMP-003 termination owner.

## Alternatives considered

Hard process termination as the normal cancellation mechanism and replaying all completed branches were rejected.

## Rationale

The decision adds only the minimum concurrency capability justified by the NorthStar workflow while keeping probabilistic reasoning, authority and protected-state mutation outside the concurrent branch runtime.

## Consequences

- Lower wall-clock latency is possible for independent I/O-bound work.
- More execution states, cancellation races, duplicate-delivery conditions and operational metrics must be handled.
- The local reference is not a production distributed queue or exactly-once system.

## Risks and mitigations

Risks are recorded in `RSK-180`–`RSK-203`; mitigations include hard bounds, typed records, idempotency, deterministic ordering, checkpoints and fail-closed authority assertions.

## Review trigger

Review for lease/heartbeat semantics, worker crash detection and durable workflow-engine adoption.
