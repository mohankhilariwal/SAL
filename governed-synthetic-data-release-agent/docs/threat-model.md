# Threat model

## Assets and boundaries

Restricted source data, candidate data, policy configuration, approval records, evidence, export receipts and identity assertions are the primary assets. User text and model output are untrusted. The export gateway is the final release boundary.

## STRIDE summary

| Threat | Example | Control | Test |
|---|---|---|---|
| Spoofing | requester or recipient impersonation | active-role validation, named recipients, separate approver IDs | policy and workflow tests |
| Tampering | policy/evidence/candidate modification | stable policy version, manifests, audit hash chain, candidate hash, approval version binding | audit/evidence tests |
| Repudiation | denied tool attempt omitted | append-only SQLite metadata plus JSONL event chain | audit test |
| Information disclosure | copied identifiers or rare profiles | deterministic classification, SDV generation, exact/near/rare gates, quarantine | scenario 3 and export tests |
| Denial of service | excessive rows, retries, model calls | budgets, timeouts, maximum rows and kill switches | policy and kill-switch tests |
| Elevation of privilege | agent self-approval or policy override | role separation, single-use approvals, PDP ownership, tool denial | approval and injection tests |

## Agentic threats

- **Prompt injection:** malicious authority claims are detected as content, not authorization.
- **Tool poisoning:** tools are represented by fixed application methods; the request cannot register a tool or alter its contract.
- **Data exfiltration:** no URL export exists; only two logical destinations map to controlled paths.
- **Excessive agency:** the workload agent cannot modify policy, metrics, approval or export state.
- **Approval bypass:** requester and agent IDs are rejected; both roles are required for external release.
- **Policy tampering:** policy version and inputs/outputs are evidence artifacts; production should protect policy in a separate administrative plane.
- **Evidence tampering:** local SHA-256 manifests and event chaining reveal changes; production requires immutable storage and stronger signing/attestation.
- **Model unavailability:** timeout and deterministic fallback preserve the governance flow.
- **Privacy-metric manipulation:** metrics receive source/candidate data directly and are not generated by the LLM.
- **Recipient impersonation:** a named partner and fixed destination are required; production must bind enterprise identity and contract metadata.
- **Export replay:** idempotency key and receipt make identical retries safe and conflicting replays rejectable.
- **Dependency compromise:** pinned tested environment, lock capture, least dependencies and CI scanning are recommended.

## Residual risk

No local demonstration can prevent a machine administrator from copying or replacing files. The released-directory receipt lets downstream validation reject unreceipted files, but operating-system and storage enforcement belong in production infrastructure.
