# Build stages

## Stage 1 — Architecture and repository

Established ports-and-adapters boundaries, typed domain models, configuration, persistence, migration, policy, model, data, export, notification and observability ports, plus the FastAPI and Streamlit edges.

## Stage 2 — Working vertical slice

Implemented request intake, identity and delegated-authority checks, fictional source-data generation, deterministic classification, candidate generation, policy evaluation, evidence creation and controlled internal export.

## Stage 3 — Governance and evaluation components

Added deterministic utility and privacy measures, versioned policy IDs, budget and kill-switch controls, optional OPA and Ollama adapters, prompt-injection controls, durable approvals, quarantine, redacted hash-chained audit events and idempotent export receipts.

## Stage 4 — Test data and live scenarios

Added four scenario request vectors, a reproducible 2,000-row fictional source generator, deterministic 5,000-row candidate generation, unsafe leakage injection, and CLI/UI one-click scenario execution.

## Stage 5 — Testing and evidence pack

Added unit, integration, policy, security, workflow and acceptance tests; sample evidence for every scenario; environment, API, package, scenario and evidence-verification reports; and the Mac demo runbook.

## Stage 6 — Production portability

Added Docker definitions, PostgreSQL/object-storage/workflow/identity/telemetry replacement guidance, AWS/Azure/GCP IaC baselines, ADRs, threat/privacy/evidence models, VERDICT and SEALED mappings, and implementation-aligned Mermaid diagrams.
